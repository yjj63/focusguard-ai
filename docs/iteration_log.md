# FocusGuard AI 关键迭代记录（AI 协作过程留痕）

> 本文档用于记录《人工智能基础与应用》课程项目从选题规划到最终部署的完整 AI 协作与多轮迭代过程，后续将整理导出为 PDF 附件提交。

## 节点 0：选题规划与技术架构确立
- **背景与约束**：需提交可部署在 GitHub Pages 的静态网页作品、源代码与中间过程、Word 实验报告及带迭代标注的 AI 交互记录 PDF。
- **关键决策**：
  1. 选定“AI + 视觉交互：基于浏览器端深度学习的实时专注度与坐姿健康助手（FocusGuard AI）”。
  2. 采用纯前端静态架构 + Google MediaPipe FaceLandmarker（WebAssembly 本地推理），无需后端服务器与 API Key，保护用户摄像头隐私。
  3. **防翻车设计一（同源本地化模型）**：将 `vision_bundle.mjs`、WASM 运行时与 `face_landmarker.task`（3.58 MB）直接本地化打包进 `assets/` 目录，避免国内网络访问 Google Storage 失败。
  4. **防翻车设计二（无摄像头模拟演示模式）**：内置 `DemoSimulator`，确保无摄像头设备也能完整体验五类姿态/疲劳状态检测与交互联动。

## 节点 1：v1.0 基础原型搭建
- **本轮目标**：完成双栏监测界面、MediaPipe 本地推理接入、头部欧拉角与 Blendshapes 提取、标准坐姿校准、异常持续时间防抖判定、Web Audio 声音提醒与无摄像头演示模式。
- **核心模块**：
  - `index.html` + `css/style.css`：深色仪表盘界面与响应式布局。
  - `js/analyzer.js`：从 4×4 变换矩阵提取 Pitch/Yaw/Roll，结合 `eyeBlink`、`jawOpen` 与人脸占比计算 0–100 综合专注评分。
  - `js/demo.js`：五种典型场景（标准专注、低头驼背、离屏过近、疲劳闭眼、左右走神）的实时模拟引擎。
  - `js/app.js`：摄像头/演示模式切换、本地模型 GPU/CPU 自动回退与事件日志记录。
- **验证发现的问题**：
  1. 手机无法通过 `localhost:8088` 访问本机测试服务，且普通局域网 `http://` 下手机浏览器安全策略会禁用摄像头——确认必须通过 GitHub Pages 的免费 HTTPS 完成公网部署。
  2. 仅有瞬时读数和日志，缺少**时间维度的趋势可视化**、**异常类型统计**、**算法阈值自定义**与**学习报告导出**。

## 节点 3：v3.0 正式版迭代（当前版本）
- **本轮优化目标**：将工具从“单次实时检测器”升级为完整的“AI 学习专注与体态健康助手”，增强视觉直观性、长期追踪能力与演示丰富度。
- **具体改进内容**：
  1. **新增视频画面 3D 头部姿态方位仪 HUD**：在实时监测窗口右下角叠加动态姿态准星，以安全中心圈、Roll 旋转十字轴与 Pitch/Yaw 偏移向量直观呈现 AI 模型的三维头部姿态解算结果。
  2. **新增番茄专注时钟（25/15/5 分钟）智能联动**：计时结束后自动保存本次学习记录、语音播报鼓励并弹出健康总结报告。
  3. **新增 20-20-20 护眼与颈椎放松引导弹窗**：提供 20 秒远眺倒计时与三步颈椎舒缓引导，形成“监测—提醒—放松”完整健康闭环。
  4. **新增 `js/storage.js`（本地历史学习档案）**：基于 `localStorage` 持久化保存最近 12 次学习记录（时长、平均分、专注率、最高频问题），刷新不丢失且完全本地化。
  5. **新增深色 / 浅色双主题一键切换**：适配日间/夜间学习场景与不同评阅展示偏好。

## 节点 4：v4.0 正式版——GitHub Pages 上线、系统性根因排查与全面验证
- **部署上线**：已将项目 16 个完整文件（含 `.nojekyll` 与本地模型）上传至 `https://github.com/yjj63/focusguard-ai`，开启 GitHub Pages 并启用强制 HTTPS，获得公网链接 `https://yjj63.github.io/focusguard-ai/`。
- **真机实测与逐行代码审查定位出的 6 个真实根因**：
  1. **移动端摄像头启动竞态**：原 `getUserMedia` 强约束横屏分辨率且未等待 `loadedmetadata` 即 `play()`，在 iOS 移动端触发异常。
  2. **未校准默认 `faceScale=0.28` 挡死歪头/走神**：手机自拍距离下人脸占比天然达 `0.45–0.60`，未校准时 `tooClose` 长期超标，而在旧版固定 `if/else if` 顺序中 `TOO_CLOSE` 排在 `TILT` 与 `DISTRACTED` 前面，直接挡死了歪头和走神提醒。
  3. **3D 矩阵坐标系歧义与正负号抵消**：旧版尝试把 3D 变换矩阵 Roll 与 2D 眼角倾角取均值导致符号互抵；且矩阵行列/缩放易随设备波动。
  4. **固定几何 EAR 阈值引发摘眼镜误报/失效**：曾尝试硬编码 `EAR=0.23`，但亚洲人自然睁眼与戴/摘近视眼镜（凹透镜缩小效应）个体差异极大，导致睁眼误报抢占最高优先级；而在部分角度下纯 Blendshape 又偏低导致漏检。
  5. **`detectForVideo` 帧同步与容错不足**：原代码在 120Hz 刷新率下对同一视频帧重复喂入浮点时间戳且缺少 `try/catch`，一旦单帧波动即中断循环假死；移动端 WebGL GPU delegate 偶发上下文丢帧。
  6. **竖屏视频与 Canvas 叠加层比例错位**及导出报告残留旧版本号。
- **v4.0 最终系统性重构与验证结果**：
  1. **直接 3D 关键点姿态解算（`js/analyzer.js`）**：用 MediaPipe 478 维 3D 关键点（额头 `10`–下巴 `152`、双脸侧 `234`–`454`、双外眼角 `33`–`263`）经画面真实像素宽高校正直接计算 Pitch/Yaw/Roll，彻底消除坐标系与正负号歧义，与镜像自拍方向 100% 一致。
  2. **自动初始校准 + 自适应个人睁眼 EAR 基线**：开启摄像头前 10 帧稳定人脸自动记录个人坐姿基准与自然睁眼 EAR（70 分位），并在清醒帧缓慢自适应上调（适配中途摘眼镜光学变化）；仅当相对本人睁眼闭合超 35% 时才与深度网络 Blendshape 融合补强。
  3. **公平多异常仲裁**：高危疲劳闭眼保持最高优先级，其余异常按超标严重倍数排序展示，彻底解决轻微前倾挡住剧烈歪头/走神的问题。
  4. **帧同步、移动端稳定化与像素对齐（`js/app.js` + `css/style.css`）**：仅在 `video.currentTime` 变化时以严格递增整数时间戳推理并加 `try/catch`；移动端自动优先稳定 CPU/WASM delegate（置信度 0.40）；视频容器与 Canvas 统一按视频真实比例 `object-fit: contain` 对齐；清理全部残留旧版本号。
  5. **自动化验证通过（8/8 PASS + 浏览器端到端 0 报错）**：在真实 Chromium 中验证本地模型加载正常、全部 UI 弹窗与主题切换正常，且 8 组核心算法单元测试（竖屏近距自动校准、快眨眼防误报、摘眼镜睁眼安全与低 Blendshape 闭眼检出、左右歪头 `±16°`、左右转头 `±24°`、低头 `+20°`、多异常公平仲裁、空帧/NaN 容错）全部通过。
